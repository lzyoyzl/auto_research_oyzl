# 借鉴了哪些研究系统

| 系统 | 原始资料中可核实的做法 | 当前项目实际采用的部分 |
|---|---|---|
| FARS | 独立的研究阶段通过共享目录交接研究提案、代码、日志和稿件。作者报告首次部署生成 166 篇稿件、覆盖 67 个细粒度 AI/ML 主题；其志愿评审也发现实验过窄、方法和完整性问题。 | 参考其组织方式，每项研究单独保存完整历史。开发失败、选题转向和草稿修订都可追溯。这里使用本地控制器，未接入 FARS 服务。[作者论文](https://arxiv.org/abs/2606.31651) |
| ARIS | 执行与审查分工，从原始数据到主张建立对应关系，再核验写作。 | 保留上游 Codex 实验规划技能；写作保存主张表。命令行各阶段使用新的 Codex 上下文，默认可使用同一模型；不将这种配置称为独立双模型复核。[作者报告](https://arxiv.org/abs/2605.03042) · [本地技能](../.agents/skills/experiment-plan/SKILL.md) |
| AutoResearchClaw | 提供用于知识提取、生成假设、研究决策和论文审查的阶段指令，系统区分继续优化与换假设。 | 实际载入固定提交中的四组提示，按本项目的文件协议输出。审稿提示只采用可适用于不同会议的部分。控制器另行运行实验并记录测量值。[上游提示库](https://github.com/aiming-lab/AutoResearchClaw/blob/be4ba4755bf1b52220f25e13b2293b5956590070/prompts.default.yaml) · [MIT 许可](upstream/LICENSE) |
| SciDER | 将数据分析、实验执行和审查结合，强调从原始数据得到可复验结论。 | 参考其数据检查思路，要求说明数据来源、标签、划分与误差，保存真实运行输出。未部署 SciDER 模型。[作者论文](https://arxiv.org/abs/2603.01421) |
| Karpathy autoresearch | 固定可比的评测规则，记录尝试，在预算内反复测量。 | 每轮冻结实验代码和方案，区分开发与确认，保留日志。[作者仓库](https://github.com/karpathy/autoresearch) |

“生成稿件数”和“经会议接受的论文数”是不同的指标。本项目交付的是供作者复核的论文草稿和证据。
