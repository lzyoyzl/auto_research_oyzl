# 论文 Design 怎样闭环

选题时交代最关键的技术关系和检验办法。获选后把方法写成可以复现、可以被反证的设计，再按下面的关系组织论文。

| 读者需要判断什么 | Design 应写清的内容 |
|---|---|
| 研究对象和输出是什么 | 给出输入、最终交付物、使用场景、评价单位、可用信息。区分校准或训练时能看到的信息与部署时可见的信息。写清固定条件、可调变量、可行域和基线解。 |
| 为什么局部改变会影响最终决定 | 沿一次实际执行从干预推到端到端指标。若声称等价、上界、因果或近似，写出前提和关键推导。给一个边界或反例，说明哪种改动会使结论失效。暂缺依据的箭头须有单独检验。 |
| 如何得到可用的解 | 说明候选如何产生、目标和约束如何计算、多个样本或资源如何共享决定、同分和不可行条件怎样处理，以及最终产物如何执行。理论与测量工作对应地给出证明步骤或可识别的对照。 |
| 什么时候停止，解有多好 | 用精确小实例、参考实现、正负对照、界或误差分析校验关键步骤。区分搜索未充分、设计空间可改善幅度小、测量无力和实现错误。用适合该主张的证据报告剩余不确定性。 |
| 代价和收益出现在哪一步 | 说明主要计算、内存和数据开销以及最坏情形。比较朴素实现和强对照，在同目标下隔离实现收益，在同预算下比较最终决策，计入准备与部署成本。 |

**把方法写回实验。** 为每项主张配上直接观测、只替换该机制的公平对照、最终任务指标和推翻条件。先检验代理量与真实执行的一致性，再用独立数据评价实际收益。小例子的最优值只描述相应的候选空间和样本。

例如，在延迟约束下选择批处理策略，可用固定到达轨迹上的离线穷举测量调度改善空间，再用只见历史队列的策略回放相同轨迹，最后比较独立负载上的端到端尾延迟。离线最优解使用了未来到达信息，说明这项限制才能解释它和在线策略之间的差距。

写作时把推导、算法在有限资源下的结果和独立评测分开表述。审稿时从最终主张反推至部署条件、目标与输入，遇到未覆盖的环节就收窄结论或安排能区分解释的实验。
